# 个人书摘检索器（从 0 到 1 练手）

## 这是什么

一个最小的 RAG 检索练手项目：50 条书摘、40 道测试题，对比关键词检索、向量检索、混合检索，再到 Agent 调度检索，四种方案在同一批问题上的表现。

不是产品，目的只有一个：亲手走一遍「造数据 → 关键词检索 → 向量检索 → 混合检索 → Agent 调度 → 评估」，并看清每种方法**失手在哪一层**。

## 文件

- `notes.json`：50 条书摘，`{id, text}`
- `questions.json`：40 道题，`{id, question, gold_ids}`
- `search.py`：关键词检索（bigram + 停用词，纯 Python）
- `vector.py`：向量检索（硅基流动 `BAAI/bge-m3`）
- `hybrid.py`：RRF 融合两路结果
- `agent_rag.py`：把向量检索包成 `@tool`，由 Agent 决定怎么查
- `evaluate.py`：跑三种检索方式，输出命中数与失手列表

## 结果

| 方式 | 命中 |
|:---|:---|
| 关键词 | 35/40 |
| 向量 | 39/40 |
| 混合（RRF） | 39/40 |
| Agent 多查询 | 单题验证（见下） |

**混合没有超过向量单独用。** 这不是 bug，是 RRF 等权融合的固有特性。

## 四种方案的失败模式（核心结论）

| 方案 | 失手在哪 | 典型题目 |
|:---|:---|:---|
| 关键词 | 字面零重叠 | 7、14、20、25、35：用户换了说法，bigram 对不上 |
| 向量 | 查询表达（抽象词 vs 具体动作） | 31：问“行动力”，gold 是“先做五分钟”，向量没关联上 |
| 混合 | 一路跑偏时噪声被放大 | 20：关键词完全跑偏，RRF 把向量的正确答案挤出 top-3 |
| Agent | — | 31：自己把“行动力”拆成“如何开始行动”，用同一个向量检索捞回了 id=31 |

**关键区分：Agent 救回第 31 题，救的是“查询表达”，不是“检索方法”。** 它底层的 `search_notes` 调的还是同一个 `vector_search`、同一个模型、同一个向量库，变的只是问法。所以：

- 关键词死在**方法本身的边界**（字面不重叠，换什么查询都可能对不上）。
- 向量死在**查询表达**（有能力理解语义，只是抽象词没触发到关系）。
- 混合**救不了查询表达问题**，它只是合并两个固定查询的结果，不会换问法。
- Agent 是**唯一能改变“输入”的方案**，所以能救“查询表达”类失手。

## Agent 单题验证（第 31 题）
用户：怎么让自己更有行动力？
Agent 并行发起两个查询：

"行动力 拖延"

"如何开始行动 迈出第一步"

- 第 1 次检索命中 id=3（gold 之一）。
- 第 2 次检索命中 id=31（gold 之一）。
- gold 是 `[1, 2, 31, 32]`，命中 2 条，且回答引用了 id=3、2、31、43、44、26，回答质量合理。

对比：向量单独用这题返回 `[44, 28, 27]`，全错。

## 评估口径与局限（重要）

**召回率的数字很大程度上取决于 gold 怎么标。** 本项目的结论必须放在下面这个口径下理解：

1. **命中判定是宽松的**：`gold_ids` 里**任意一条**出现在 top-3 里，就算这题命中。如果改成“gold 里每一条都要被召回”，数字会明显下降。
2. **gold 条数不等**：有的题标 1 条，有的标 4 条（如第 31 题 `[1, 2, 31, 32]`）。标 4 条的题命中难度天然更低，这会让整体命中率偏高。
3. **gold 由单人标注，存在歧义**：第 31 题混合靠 `32` 命中，但 32 和 44、6 一样，都不是最直接回答“行动力”的那条，它只是碰巧在 gold 列表里。这说明**谁在 gold 里，谁就“生”**。
4. **样本小**：40 题，1–2 题之差不足以支撑强结论。数字的价值在“定位失败模式”，不在“精确排名”。

**一句话：39/40 不是“向量检索准确率 97.5%”，而是“在这个 gold 标注和宽松命中口径下，40 题里 39 题至少召回了一条标注为相关的结果”。**

## 如果想继续

- 给混合加权（`kw_weight=0.3`），验证能否到 40/40
- 换 jieba 分词，看关键词单独能否从 35 提升
- 把 Agent 从“一次性多查询”改成“打分 + 条件重试”（LangGraph Agentic RAG 正统做法）
- 对 Agent 检索结果做 rerank，看回答质量能否再上一层
